GPU 3장(RTX PRO 4500 Blackwell 32GB / RTX A6000 48GB / RTX 4090 24GB)에 직접 접근된다.

**그래서 앞으로**:
- 실험 명령을 **문서에 적어 사람에게 넘기지 않는다.** AI가 직접 실행하고, 긴 것은
  tmux/백그라운드로 띄운 뒤 완주를 기다렸다가 `results/`를 읽고 판정·커밋한다.
- 사람은 실험 설계 결정(어느 suite·모델·k값 등)과 결과 해석만 맡으면 된다.

**운영 규칙 (상세는 부록 B-9)**:
1. **매 Bash 호출마다 `source env.sh`를 다시 한다** — 호출마다 새 셸이라 venv 활성화가
   안 남는다. 형식:
   `cd ~/head_poc && source env.sh >/dev/null 2>&1 && CUDA_VISIBLE_DEVICES=N python ...`
   ⚠️ `source env.sh`를 **파이프에 물리면 서브셸에서 실행돼 활성화가 안 된다.**
   리다이렉트는 괜찮음.
2. **긴 실행은 tmux 안에서** (`tmux new -d -s jb-<name> '...'`) — SSH/세션 끊김 대비.
   `tmux capture-pane -t <name> -p | tail` 로 진행 확인.
3. **GPU 인덱스는 매번 `gpu_free` + 이름 검증.** `CUDA_DEVICE_ORDER=PCI_BUS_ID`는
   env.sh가 잡지만 4090 추가 이후 인덱스 이력이 있어 안전하게.
   - **4bit 32B 평가 = 반드시 A6000** (Blackwell nf4 커널이 32B 손상, §아래 유지).
   - 7~8B bf16 = 4090. 큰 스케일업 = A6000.
4. **커밋은 이 세션에서.** git 로컬 스코프가 이미 `Won` / `jongbinwon03@gmail.com`.
   결과·문서 모두 서버에서 커밋·push → 로컬 클론은 pull. "코드/문서는 로컬에서만"
   관례 완화.

## 2. 실험 상태 (2026-09-07에서 이어짐 — 변화 없음)

P16(교수님 피드백 4번) 사이클은 **완전 종결**. 4차 발표 자료(`docs/presentation/`)도
완성 — pptx는 발표일 확정 시 `build_deck_4th.py`의 `OUT` 경로 날짜(`[26-09-XX]`)만 수정.

핵심 결론 (상세는 status-2026-09-07 §1, feedback §1·§2.1):
- **스케일업 반례 재확인** — 32B는 slack의 달성 가능 공격(injection_task 1/3/5)을
  knockout으로 절반 이상 못 막음(8~9→5). 8B급은 전량 억제(6→0).
- **복합 공격 2/4의 0%는 연언 채점 아티팩트** — 분석 제외.
- **32B nf4dq는 GPU 고정 시 결정론적.** 2.1.17 "비결정성"은 오진 —
  **A6000(sm_86) ↔ Blackwell(sm_120) 아키텍처 차이**. Blackwell bnb 0.50.1 nf4 dequant
  커널이 32B를 손상(slack k0_util 0.286→0.086 붕괴). **→ 4bit 32B 평가는 A6000 고정.**
