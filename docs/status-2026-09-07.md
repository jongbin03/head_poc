### B. 32B 4bit "비결정성" 규명 → GPU 아키텍처 차이 (feedback 2.1.20)

**배경**: 2.1.17에서 nf4dq #1(A6000) ↔ #2(Blackwell)가 slack 35쌍 중 12쌍 불일치 →
"32B-4bit 평가는 run-to-run 비결정적"으로 판정, 스케일 효과는 bf16(2.1.18)으로만 확정.

**검증** (`results/2026-09-07_p16f_32b_nf4dq_samegpu/`): `--suite slack` 단독 nf4dq를
같은 GPU에서 반복.
- **Blackwell ×5** (2.1.17 + 신규 3회 + GPU 인덱스 오설정으로 Blackwell에 떨어진
  "a6000" 2회): slack 35쌍 전부 4필드 일치.
- **A6000 ×3** (2.1.15의 4-suite 실행 slack 부분 + 신규 slack-only 2회): 역시 전부 일치.

**결론**:
1. **32B nf4dq는 GPU 고정 시 완전 결정론적** (7B와 동일). 2.1.17 "비결정적" 판정은 오진.
2. **12/35 불일치 = A6000(sm_86) ↔ Blackwell(sm_120) 아키텍처 차이**. 계통적:
   `slack/user_task_0`(injection 5변형 전부)·`user_task_2`가 A6000에선 k0_util True,
   Blackwell에선 False.
3. **Blackwell bnb 0.50.1 nf4 dequant 커널이 32B를 손상** — slack k0_util이 A6000 nf4dq
   0.286(= bf16 0.286)에서 Blackwell nf4dq **0.086**으로 붕괴(baseline 과업 실패). 신규
   아키(sm_120) 커널 미성숙.
4. → **A6000 nf4dq가 신뢰 가능한 4bit 실행**(bf16과 baseline 일치), Blackwell nf4dq는
   신뢰 불가. **4bit 32B 평가는 A6000에 고정.**
5. **스케일 효과(2.1.18) 판정은 그대로 유효 + 보강** — A6000에서 양자화만 바꾼 결정론적
   비교: nf4dq는 slack knockout 순효과 0(kN_sec 0.229 = k0_sec), bf16은 순효과 −4
   (0.257→0.143). 4bit 잔여 손상이 knockout을 더 나빠 보이게 하지만 **두 경우 다 8B(전량
   억제)에 못 미침**. S14 한계 1번("32B-4bit 비결정성 원인 미규명") 해소.

**⚠️ GPU 인덱스 함정**: `CUDA_VISIBLE_DEVICES=<n>` 지정 시, aisec-king에 RTX 4090이
추가되면서 인덱스가 바뀜(부록 B 경고). 실행 전 반드시
`CUDA_VISIBLE_DEVICES=<n> python -c "import torch; print(torch.cuda.get_device_name(0))"`
로 GPU 이름 검증. (이번에 "a6000" 파일명 2개가 실제로는 Blackwell에서 돌아 재실행함.)
